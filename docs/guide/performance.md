# 성능

## 앱 코드에서 지킬 것

### 연속 값은 구독한 만큼만

엔진은 캐릭터 위치나 카메라 상태를 **구독한 경우에만** 보냅니다. 화면에 필요한 곳에서만 `useCharacterPosition` / `useCameraState`를 쓰고, `throttleMs`를 넉넉하게 주세요 (기본 250 ms). 같은 토픽은 엔진 구독 하나로 공유됩니다.

### 라벨 내용 함수는 필요할 때만 다시 평가

`labels.content` 함수는 모든 라벨에 대해 실행되지만, 새 `labelsIndex`가 올 때, `labels`의 함수가 아닌 필드가 바뀔 때, `ref.refreshLabelContent()`를 부를 때만 실행됩니다. 렌더마다 인라인 함수를 새로 만들어도 다시 계산하지 않으므로 `useCallback`은 필요 없습니다. 함수가 읽는 데이터가 바뀐 경우에만 `refreshLabelContent()`를 부르세요. [라벨](./labels#커스텀-내용)을 보세요.

### 자식 컴포넌트는 알아서 묶인다

`Character`, `CharacterLayer`, `DropLayer`, `Geofence`, `MapOverlay`의 변경은 애니메이션 프레임마다 **종류별 명령 최대 1개**로 합쳐집니다. 배열을 자주 갱신해도 괜찮지만, `getId`가 안정적인 id를 돌려줘야 diff가 작아집니다.

### 오버레이는 React 렌더 없이 움직인다

`MapOverlay`의 위치는 `Animated` 값으로 적용됩니다. 오버레이 안의 컴포넌트는 `memo`로 감싸 두면 카메라 이동 중 렌더가 0회입니다.

## v1 웹 엔진 (WebView)

### 필요할 때만 그립니다 (온디맨드 렌더)

엔진은 **무언가 움직일 때만** 프레임을 그립니다. 아무도 건드리지 않는 지도는 렌더 0프레임이고,
시뮬레이션도 함께 멈춥니다. 프레임을 깨우는 것은 다음과 같습니다.

- 명령(`setCamera`, `setTheme`, `upsertCharacters` …) 하나당 한 프레임
- 제스처·줌 버튼·탭, 컨테이너 리사이즈, 늦게 도착한 glTF 모델, `device` 위치 픽스
- 애니메이션이 있는 서브시스템: 캐릭터, 여행, 드롭, 지오펜스 펄스, 주변 교통, 시뮬레이션 워커,
  줌아웃·카메라 이징, 회전하는 랜드마크와 점령 건물의 발광, 사라지는 중인 홀로 라벨

기기의 "동작 줄이기"(`prefers-reduced-motion`)를 켜면 캐릭터 숨쉬기·지오펜스 펄스·건물 발광·
카메라와 줌아웃 이징이 모두 접히므로, 정적 지도는 **완전히** 쉽니다. 반대로 지도가 계속 그려지는
경우는 대개 콘텐츠 때문입니다.

| 계속 그리는 원인 | 끄는 방법 |
| --- | --- |
| 캐릭터 (기본 아바타는 숨쉬기, glTF는 idle 클립) | 필요 없으면 `removeCharacters`, 또는 동작 줄이기 |
| 주변 교통 (`urban`·`modern`·`soft` 프리셋 기본값) | `theme.street.traffic: false` |
| 드롭 (항상 공중에서 돌고 떠다닙니다) | 화면에서 치우면 멈춥니다 |
| 회전하는 랜드마크·점령 건물 발광 | 동작 줄이기 |
| `locationSource: 'simulated'` 데모 워커 | `follow: 'location'` 캐릭터가 있을 때만 돕니다 |

RAF 콜백 자체는 계속 돌지만(본문만 건너뜁니다) 그 비용은 무시할 수 있습니다. 완전한 취소와
백그라운드 탭 게이트는 아직 남은 과제입니다.

### 가장 큰 절약: 2D 뷰 모드

저사양 기기에서 무거우면, 테마를 깎기 전에 **뷰 모드**를 먼저 보세요. `view="2d"`는 돌출 지오메트리와
그림자 패스를 통째로 빼고 건물을 색상별 병합 메시 하나 + 외곽선 하나로 그립니다. 성수 OSM 샘플(건물 428)
기준으로 드로우 콜이 프레임당 2,950 → 29, 패닝 fps가 5.9 → 17.4입니다(자세한 표와 측정 방법은
[2D ⇄ 2.5D 뷰 모드](./view-modes.md)). 정적일 때 유휴 프레임 0은 두 모드 모두 그대로입니다.

### 그림자는 바뀐 프레임에서만 다시 굽습니다

프레임 비용의 대부분은 `render()`이고, 그 절반 가까이가 태양 그림자 맵(2048², 모바일 1024²)을
다시 그리는 깊이 패스입니다. 엔진은 **그림자를 드리우거나 받는 무언가가 실제로 바뀐 프레임에서만**
이 패스를 실행합니다.

- 태양(= 카메라 중심을 따라갑니다)이나 줌아웃으로 넓어지는 그림자 절두체가 움직였을 때
- 3D 장면을 건드리는 서브시스템이 아직 움직이고 있을 때 (캐릭터·여행·드롭·주변 교통·건물 바운스,
  그리고 알 수 없는 태그로 잡은 활성 소스 전부)
- 프레임 밖에서 장면이 바뀌었을 때 (명령 하나, 테마·월드 재생성, 늦게 도착한 glTF 모델)

그래서 **카메라를 제자리에서 돌리거나 당기는 프레임, 홀로 라벨만 사라지는 프레임, 호스트 오버레이만
옮기는 프레임은 그림자 맵을 그대로 재사용합니다.** 화면 결과는 같습니다.

반대로 주변 교통이나 회전하는 랜드마크가 켜져 있으면 장면은 매 프레임 실제로 움직이므로 그림자도
매 프레임 다시 그려집니다. 조용한 지도를 원한다면 위 표대로 `theme.street.traffic: false`와
"동작 줄이기"를 쓰세요 — 프레임 수와 그림자 비용이 함께 내려갑니다.

측정(헤드리스 Chrome, ANGLE Metal, 390×760, 절차적 town/urban/day, 프레임 400개 × 3회 중앙값):
교통과 랜드마크 회전을 끈 장면에서 카메라를 계속 회전시키면 프레임당 `render`가 2.32 ms → 1.59 ms,
그림자 패스가 1.05 ms → 0.02 ms로 내려갑니다.

### 오버레이 앵커는 보낼 수 있는 프레임에서만 투영합니다

`overlay:positions`는 33 ms에 한 번까지만 나갑니다. 엔진은 **투영 전에** 이 스로틀을 먼저 확인하므로
창 안에 있는 프레임에서는 앵커를 하나도 계산하지 않고, 앵커의 월드 좌표는 앵커 집합이나 월드가
바뀔 때까지 캐시하며, 프레임 배치는 재사용 버퍼에 씁니다. 이벤트는 여전히 **모든 앵커**를 담습니다
(화면 밖 앵커의 `x`/`y`도 `hideWhenOffscreen={false}`에서 쓰이기 때문입니다).

### 그 밖에

- 엔진은 약 900 KiB짜리 인라인 HTML(`engine.html`) 하나로 WebView에 들어갑니다. 따로 내려받는 엔진 파일은 없습니다.
- WebView는 투명·비스크롤로 렌더링되고, 메시지는 문자열 봉투(`{"v":1,"seq":N,"kind":"cmd"|"evt","msg":…}`)로 오갑니다. 큰 월드를 `data`로 인라인하면 이 문자열이 커지므로 `url`을 권장합니다.
- 월드가 로드되기 전에 보낸 캐릭터, 드롭, 지오펜스는 엔진이 보관했다가 적용하므로 `onReady`를 기다렸다가 자식 컴포넌트를 렌더링할 필요가 없습니다.
- Android 렌더 프로세스가 죽거나 iOS 콘텐츠 프로세스가 종료되면 WebView를 다시 만들거나 새로고침하고, `init`과 모든 선언형 상태를 다시 보냅니다. 진행 중인 `travel`은 `engine_reloaded`로 reject됩니다.
- 기기의 "동작 줄이기" 설정(`prefers-reduced-motion`)을 따라 카메라 애니메이션을 줄이고, 위에 적은 대로 정적 지도를 완전히 쉬게 합니다.

## v2 네이티브 엔진 예산

기준 기기(iPhone 12 / Pixel 6a급)에서 성수 샘플을 건물 20,000동으로 늘린 장면의 **목표치**입니다. 모두 M4에서 측정하기 전의 추정이고, 실측이 생기면 CI 성능 게이트로 바뀝니다.

| 항목 | 목표 |
| --- | --- |
| 프레임 | 60 fps에서 16.6 ms (p95). 코어 틱 ≤ 2 ms, 디오라마 인코딩 ≤ 4 ms, MapLibre 베이스맵 ≤ 5 ms |
| 네이티브 힙 | 엔진 전체 ≤ 250 MB (타일 캐시 50 MB, 디오라마 지오메트리 ≤ 60 MB, 텍스처 ≤ 64 MB, 캐릭터당 ≤ 8 MB) |
| 드로 콜 | 프레임당 ≤ 150 (건물 256 m 셀 청크, 드롭은 종류 × 희귀도당 1, 라벨 ≤ 3) |
| 캐릭터 | 스키닝 ≤ 32명, 캐릭터당 관절 ≤ 64 |
| 드롭 | 활성 ≤ 5,000, 화면 ≤ 1,500 |
| 라벨 | 인덱스 ≤ 1,000, 프레임당 배치 ≤ 300 |
| 메시지 디코드 | 일반 명령 ≤ 0.2 ms, 5 MB 인라인 월드 `init` ≤ 150 ms (워커, p95) |
| 지연 | JS `send` → 적용 ≤ 1 프레임, 이벤트 → JS 핸들러 ≤ 1 프레임 |
| 콜드 스타트 | 뷰 마운트 → `ready` ≤ 300 ms, `init` → 첫 디오라마 프레임 ≤ 1 s |
| 바이너리 | ABI당 +12 MB 이하 (에셋 제외) |
| 배터리 | `device` 위치 소스 포그라운드 추가 소모 ≤ 5 %/h |

M4에서 성수 샘플에 캐릭터 51명·드롭 200개·지오펜스 20개를 올린 장면을 iOS 시뮬레이터와 Android 에뮬레이터에서 측정했습니다(**실기기는 아직 측정 전**). 코어 틱은 두 플랫폼 모두 0.4 ms 아래로 2 ms 예산 안이고, 드로 콜도 예산 안입니다. 줌아웃이 켜져 있으면 먼 거리에서 모델 드로 콜이 64개에서 1개로 줄어(아이콘 디스크) Android 에뮬레이터 기준 커스텀 레이어 비용이 5–11 ms에서 0.5–0.75 ms로, 프레임 간격이 32–47 ms에서 8–13 ms로 내려갑니다. 측정 방법과 전체 표는 `packages/engine-native/DESIGN.md` §8에 있습니다.
