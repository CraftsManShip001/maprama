# 콘텐츠 인셋 (앱 UI가 지도를 가릴 때)

바텀시트가 화면 절반을 덮는 지도 화면은 흔합니다. 문제는 지도가 그 사실을 모른다는 것입니다. 카메라는 시트 뒤에 중심을 잡고, 라벨과 마커는 시트 아래에 배치되고, **엔진이 그리는 `© OpenStreetMap` 저작자 표시가 시트에 가려집니다**.

`ui.contentInset`은 지도에게 "여기부터 여기까지는 내 UI가 덮고 있다"고 알려 줍니다. 단위는 **dp**입니다.

```tsx
<MapramaView
  ui={{ attribution: true, contentInset: { bottom: sheetHeight } }}
  camera={{ center: STATION, distance: 700 }}
/>
```

지도는 **여전히 화면 전체에 그립니다**. 시트 뒤에도 지도가 이어집니다. 달라지는 것은 "사용자가 보는 곳"의 정의뿐입니다.

## 저작자 표시는 라이선스 문제입니다

실데이터를 쓰는 지도는 데이터 라이선스(ODbL 등)상 출처를 보여야 합니다. 시트가 그걸 덮으면 **표기를 안 한 것**입니다.

"`attribution: false`로 끄고 앱이 직접 같은 문구를 그린다"는 방법은 더 나쁩니다. 라이브러리가 문구나 데이터 출처를 바꾸는 순간 앱은 **틀린 저작자 표시**를 보여주게 되고, 아무도 그걸 알아채지 못합니다. 그래서 표기는 계속 엔진이 그리고, 인셋이 그것을 시트 밖으로 옮깁니다.

`attribution: true`인 동안 시트가 표기를 덮는 일은 없어야 합니다 — 그것이 이 기능의 요구사항입니다.

## 무엇이 바뀌나

| 바뀌는 것 | 어떻게 |
| --- | --- |
| `setCamera`의 `center` | **보이는 영역**의 중심에 놓입니다. 시트 뒤가 아니라 위쪽 절반의 한가운데입니다 |
| 엔진이 보고하는 카메라 | `camera:change` / `camera:idle` / `fitBounds` 결과의 `camera.center`도 같은 점입니다 (왕복이 맞습니다) |
| `follow` | 따라가는 캐릭터가 시트 위쪽에 머뭅니다 |
| 오너먼트 | 축척 막대, 줌 버튼, 저작자 표시가 인셋 안쪽으로 이동합니다 |
| 라벨·마커 | 배치와 가장자리 클램프가 보이는 영역 기준입니다 |
| `ScreenPoint.visible` | `project`와 `overlay:positions`의 `visible`은 "보이는 영역 안에 있나"입니다 |
| `camera:idle` | `bounds`와 `radiusMeters`가 보이는 영역의 지면을 잽니다 |
| `fitBounds` | 인셋이 요청한 `padding`에 **더해집니다**. 상자는 보이는 영역 안에 담깁니다 |

## 무엇이 바뀌지 않나

- **`project` / `unproject`의 좌표계**. 화면 좌표는 계속 **지도 뷰 전체**의 픽셀이고 원점은 왼쪽 위 모서리입니다. 이것만은 "보이는 영역"이 틀린 기준입니다: 앱이 이 좌표로 하는 일은 자기 뷰 위에 무언가를 놓는 것(팝오버, 시트 열기, 히트 테스트)인데, 앱의 좌표계는 뷰 전체이기 때문입니다. `marker:press`의 `point`도 같습니다.
  ::: tip
  좌표는 전체 뷰 픽셀, `visible`은 "실제로 보이나". 두 가지가 한 객체에 있습니다.
  :::
- **렌더링 영역**. 캔버스는 그대로 화면 전체이고, 지도는 시트 뒤까지 그려집니다(시트가 반투명이거나 드래그로 내려갈 수 있으니 당연합니다).
- **`zoom` ⇄ `distance` 변환**. 웹맵 줌 레벨은 뷰 **전체** 높이로 정의됩니다. 인셋을 켰다고 같은 `zoom`이 다른 축척이 되지는 않습니다.
- **축척 막대의 길이**. 미터/픽셀은 그대로입니다. 막대가 있는 **위치**만 움직입니다.
- **제스처**. 터치 좌표는 뷰 전체 기준입니다(시트가 덮은 곳의 터치는 애초에 시트가 가져갑니다).

## 인셋을 켜면 지도가 움직입니다

인셋을 켜면 카메라가 보던 지면의 점이 **보이는 영역의 중심**으로 옮겨 갑니다. 즉 지도가 위로 미끄러집니다. 이것이 의도한 동작입니다: 시트를 열었는데 관심 지점이 시트 뒤로 숨으면 안 되니까요. 카메라가 움직였으므로 `camera:idle`도 한 번 더 옵니다(`reason: 'api'`).

## 시트 높이가 바뀔 때

시트를 드래그해 높이가 바뀐다면 `contentInset.bottom`을 그 높이로 갱신하면 됩니다. `ui` prop이 바뀔 때만 `setUi`가 나가므로, 드래그 중 매 프레임 갱신하기보다 **스냅 지점에서** 보내는 편이 좋습니다(그때마다 카메라가 따라 움직이기 때문입니다).

## 네이티브 엔진에서는

`engine="native"`(MapLibre Native)에서는 아직 **일부만** 구현돼 있습니다. C++ 코어는 값을 검증하고 `camera:idle`의 `bounds` / `radiusMeters`와 라벨 배치에 반영하지만, **MapLibre 카메라 패딩(중심·`follow`)과 플랫폼 오너먼트 배치는 아직 움직이지 않습니다.** 비어 있지 않은 인셋을 보내면 엔진이 한 번 경고 로그를 남깁니다. 남은 항목은 `packages/engine-native/DESIGN.md` §11.1에 있습니다.

바텀시트가 저작자 표시를 덮으면 안 되는 화면이라면, 그때까지는 웹 엔진(기본값)을 쓰거나 시트가 오른쪽 아래 모서리를 비켜 가도록 앱이 직접 맞춰야 합니다.

## 예제

예제 앱의 **11. Bottom sheet: camera:idle & content inset** 화면이 이 문서 그대로입니다: 화면 절반을 덮는 시트, 인셋 토글, 그리고 정지할 때마다 갱신되는 `camera:idle` 읽기.
