# Roadmap and current state

This file is the hand-off summary: what works today, what is known to be missing, and what the next
milestone is meant to contain. `README.md` describes the library, `packages/engine-native/DESIGN.md` the
native engine's design and parity matrix, `CHANGELOG.md` the released versions.

_Last updated: 2026-09-16._

### Native engine milestones (all merged to `main`, CI green)

- **M1** map, camera, gestures, `camera:change`, `project` / `unproject`.
- **M2a** 3D buildings (`fill-extrusion`), themes + time of day, `setBuildingStyle`, `map:press` /
  `building:press`, map UI, overlay anchors.
- **M2b (procedural)** `world: { kind: 'procedural' }` generated by the C++ core — same seed, same world as
  the web engine.
- **M2c** roofs, facade windows and details, outlines and the captured flag in a custom render layer
  (iOS `MLNCustomStyleLayer` on Metal, Android `CustomLayerHost` on GL ES 3 — no MapLibre fork).
- **M3a** characters, location sources, travel and routing, drops, geofences, `setCamera.follow`.
- **M3b** glTF characters with GPU skinning and animation, vehicles, procedural bodies, 3D drop items,
  depth-tested against the buildings (cgltf vendored, MIT).
- **M4** zoom-out game view (`theme.zoomOut`, `keepGameView`), performance and memory measurement,
  parity pass. Far-camera model draw calls 64 → 1; Android far-camera frame interval 31.7–47.3 ms →
  8.2–13.1 ms.
- **Labels (M2b)** — see "In progress" below.

## Known gaps and limitations

- **Labels on the native engine** are the last capability gap before a native beta (see below).
- **Performance numbers are simulator/emulator only.** No real-device measurements, binary size or cold
  start yet. The Android emulator translates GL on the host, so its near-camera frame times are pessimistic.
- **Deliberate visual deviations from the web engine** (documented in DESIGN.md §11): icon discs beyond the
  far zoom band and dropped facade details/roof furniture at high zoom-out factors, no street scenery or
  trees, no cinematic grading/post pass, no drop note sprites or chime, colours read slightly flatter than
  the web engine's PBR-lite shading.
- **No tile-backed worlds.** `WorldSource` is `data | url | procedural`; `{ kind: 'tiles' }` from DESIGN.md
  §7 is design only, and there is no PMTiles build pipeline. A world is one city-sized area.
- **`world` is read once at `init`.** Changing worlds means remounting the view (`key`), which rebuilds the
  style and geometry.
- Compressed glTF (Draco, meshopt) and models with more than 63 joints are rejected with
  `model_load_failed`; the procedural body is drawn instead.

## In progress

- **Native labels** (`labelsIndex`, `setLabels`, `setLabelContent`, character name tags, labels on
  procedural worlds, label zoom-out rules). The work is verified on both platforms except the final E2E
  pass at the time of writing; it lands on `main` as soon as that passes.

## Next milestone — M5: app-integration API

Driven by the first integrator (a location-based game app). Their priority order:

1. **`<MarkerLayer>`** — app-owned pins drawn by the engine: 40–60 per screen, fixed dp size, bottom-centre
   anchor, tap with screen point, priority-based collision with an "always show" option, per-marker
   `accessibilityLabel` that reaches the screen reader, and **partial updates** (changing only `color` or
   `selected` must not rebuild the marker or re-upload its icon). Icons must support either
   `data:image/svg+xml` or a two-layer base-shape + glyph form where only the base is tinted.
2. **`camera:idle`** — a camera-stopped event with `bounds`, `radiusMeters` from the centre and
   `reason: 'gesture' | 'api' | 'follow'`, used as the trigger to fetch data for the visible area.
3. **`ui.contentInset`** — top/right/bottom/left in dp affecting the camera centre, `follow` centring,
   engine ornaments, label/marker placement, `overlay:positions` and the `camera:idle` bounds, plus
   engine-drawn attribution that can be repositioned instead of switched off.

Also requested, lower priority: `ref.setWorld(source)` without a remount, `minDistanceMeters` /
`maxDistanceMeters` props and `fitBounds(bounds, padding)` (today the clamp is 14–150 **world units**, so the
metre range scales with `WorldData.unitMeters`), then tile-backed worlds with a PMTiles pipeline in
`tools/osm` and a flat basemap outside the diorama.

## Testing notes

- `npm test` runs the JS suites, the C++ core tests and the fixture conformance checks; `npm run build`
  builds workspaces in dependency order.
- End-to-end flows live in `example/.maestro/` and run with Maestro 2.10 on a simulator/emulator. The native
  flows are 05 (M1 + procedural + remount), 06 (M2a), 07 (M2c), 08 (M3a + M3b), 10 (M4).
- CocoaPods needs `LANG=en_US.UTF-8`; Android builds need `JAVA_HOME` on JDK 17 and `ANDROID_HOME`.
- Expo iOS builds break on paths containing spaces — keep the checkout on a space-free path.
